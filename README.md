# ✍️ ДЕД РЕДАЧИТ — @biletgetbot

Чатовый редактор билетов: дед за пишущей машинкой перепечатывает билеты начисто.
Убирает чужие ФИО и служебные строки, сохраняет QR-коды, штрихкоды, даты,
места и цену — каждая правка проверяется перед отправкой.
Аватар деда: `brand/ded.jpg`, приветственная картинка: `brand/welcome.jpg`.
Бот работает только через сообщения Telegram: без Mini App и веб-кабинета.
PDF и ZIP принимаются в чате, результат возвращается туда же. Оплата —
штатный счёт в Telegram Stars.

Бот работает на VDS, `/opt/bilet-bot`, сервис `bilet-bot.service` (пример юнита —
`bilet-bot.service` в репозитории). Движок автоочистки — тот же, что в «Билетной»:
распознанные шаблоны KASSIR.RU, kassy.ru, Ticketland, Intickets, Афиша/МХТ
и остальные шаблоны редактора.

## Как пользоваться (для клиентов)

1. `/start` — приветствие с кнопками. `/help` — подробная инструкция.
2. Открыть доступ: `/subscribe` (абонемент), `/promo КОД` (промокод)
   или `/trial` (бесплатный пробный день, один раз).
3. Прислать PDF-билет документом — дед вернёт `<имя>_cleaned.pdf`.
   Несколько PDF подряд (или ZIP) — вернёт ZIP + `report.txt` с реестром.
4. Под билетом кнопки: 👤 ФИО · ✏️ цена · 🪑 ряд/место/сектор ·
   🎁 скрыть цену · 🖼 «До и После» · ✂️ разбить на билеты.
5. `/profile` — профиль: статус доступа, число перепечатанных билетов, настройки.
6. `/settings` — ФИО по умолчанию, кастомная цена, скрытие цены,
   формат пачек (ZIP / склейка в один PDF / по отдельности), авто-превью.
7. `/batch` → PDF-файлы → `/done` — собрать пачку вручную; `/cancelbatch` — отмена.

## Монетизация

1000 Telegram Stars за 30 дней, без лимита обработок. Telegram автоматически
продлевает подписку каждые 30 дней. Доступ открывается только после
`successful_payment`. Администраторы из `subscription.json` имеют постоянный доступ.

- `/subscribe` — персональный счёт; `/subscription` — статус (также `/dolg`, `/balance`).
- `/cancel_subscription` — отключить автопродление, сохранив оплаченный срок.
- `/trial` — пробный день, один на аккаунт (идемпотентность через `access_actions`).
- `/promo КОД` — активировать промокод; дни суммируются с текущим сроком.

Инструменты администратора:

- `/admin` (или `/panel`) — панель: статистика, последние оплаты, промокоды,
  инциденты оплат, подсказка по рассылке.
- `/promogen КОД ДНИ [АКТИВАЦИИ]` — создать промокод (годен 30 дней).
  Пример: `/promogen THEATR2026 7 50`.
- `/broadcast ТЕКСТ` — рассылка всем пользователям бота с ограничением темпа.
- `/grant ID_или_@username дни`, `/revoke ID_или_@username`, `/payments`,
  `/refund идентификатор_оплаты`, `/payment_issues`.

Цена и администраторы заданы в `subscription.json`. `gift_usernames` выдаёт
разовый бесплатный период при сообщении от указанного Telegram username,
затем привязывает его к числовому ID; приглашение действительно 7 дней.

## Хранение данных

`state/subscriptions.sqlite3` — подписки, оплаты, возвраты, очередь,
пользователи (профиль, счётчик билетов), промокоды. WAL-режим включён
автоматически; схема обновляется миграциями `migrations/001–003`.
Файл базы нельзя включать в пакет обновления или откатывать после приёма новых платежей.

## Билеты и пачки

Во время обработки бот обновляет одну карточку в чате: получение файла,
перепечатка, проверка и отправка. Индикатор и таймер меняются примерно каждые
2,5 секунды; для ZIP и /done показано реальное число обработанных PDF и ошибок.
«Всё готово» появляется только после успешной отправки результата. При сбое
Telegram обновление карточки не прерывает обработку; ошибки выдаются отдельно.
В карточке короткие реплики ДЕДА про пишущую машинку. Создание и обновление
карточки целиком выполняются в отдельном потоке и не задерживают скачивание
или отправку билета. В журнале отдельно замеряются скачивание, перепечатка,
проверка и отправка, без имён и содержимого билетов.

Успешно отправленные PDF кешируются на 24 часа: хранятся только закрытые
метаданные и Telegram file_id, без байтов билетов. Кеш изолирован по
пользователю и чату, учитывает имя и версию кода редактора.

Новые PDF/ZIP до 20 МБ передаются Telegram по временной HTTPS-ссылке
(маршрут `/-bilet-download`, слушатель только на `127.0.0.1:4313`).
Ссылка не показывается пользователю; файл хранится в памяти, доступ закрывается
после подтверждения отправки. ZIP больше 20 МБ загружается напрямую.

Входящий файл до 20 МБ; пачка до 50 PDF и 100 МБ распакованных данных.
Выходящий ZIP до 48 МБ. PDF до 100 страниц обычного размера.
ZIP не распаковывается в файловую систему: пути, ссылки, шифрование и объём
проверяются. Неудачные PDF отмечаются в отчёте; остальные выдаются.

Перед выдачей изменённого PDF проверяются число страниц, размер, поворот,
содержимое читаемых QR/штрихкодов, изображение нечитаемых областей и
распознанные ряд, место, сектор, цена, дата и номер билета. При повреждении
файл не выдаётся. Если изменений не нужно, возвращается точная копия исходных байтов.

PDF из `/batch` хранятся в закрытой папке `state/spool` не более часа,
удаляются после выдачи или отмены. Одиночные PDF и ZIP обрабатываются в памяти.

## Надёжность

- Любая ошибка `dispatch_update` гасится и журналься — polling не падает
  от одного плохого update; процесс перезапускает systemd (`Restart=always`).
- Число рабочих потоков очереди: `BILET_WORKERS` (по умолчанию 2).
- Очистка просроченных пачек — раз в 60 секунд, а не каждый цикл.
- Схема SQLite применяется один раз при старте; включён WAL.
- IP фронтендов Telegram для `getFile` можно перекрыть:
  `BILET_TELEGRAM_EDGES=149.154.166.110,149.154.167.220`.
- Меню команд публикуется через `setMyCommands` при старте.

## Проверка и обновление

Установить зависимости в отдельное виртуальное окружение (Python ≥ 3.10):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python bot.py --self-test
./Запустить\ бота.command --deploy
```

Обновление через `deploy-vds.sh`: тесты на временном пакете, резервная копия
кода и SQLite, замена кода и перезапуск только `bilet-bot.service`. Токен,
`.env`, очередь, платежи и текущие настройки сохраняются.
Для намеренного обновления настроек задайте `BILET_DEPLOY_SETTINGS=1`.
Для первичной подготовки маршрута HTTPS задайте `BILET_GATEWAY_ONLY=1`,
затем `BILET_ENABLE_URL_DELIVERY=1` при обычном деплое включает
`BILET_PUBLIC_DELIVERY=https://theatralka.ru/-bilet-download` в серверном `.env`.
Если откат возвращает старую версию с начислениями за файл, сервис остаётся
остановленным; подписки и полученные оплаты не откатываются.

Движок, шрифты и тесты берутся из `BILET_EDITOR` (по умолчанию `~/Билетная`)
и размещаются в `/opt/bilet-bot/biletnaya`; путь задаётся `BILETNAYA`.
Токен: `.token` или `BILET_BOT_TOKEN`. Секреты и пользовательская база не
попадают в пакет. Не запускайте локальный polling одновременно с VDS.
