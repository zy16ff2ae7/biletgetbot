# МАМА · Мама кормит — @biletgetbot

Чатовый редактор билетов из одной сети с ДОЧЕЙ («Папина дочка»).
Оформление: розовый фартук с билетом в кармане, без лица и персонажа.
Тёмный сливовый фон и розовый акцент связывают МАМУ с ДОЧЕЙ.
Аватар хранится в `brand/mama.jpg`.
Бот работает только через сообщения Telegram: без Mini App и веб-кабинета.
PDF и ZIP принимаются в чате, результат возвращается туда же. Меню —
обычные команды Telegram, оплата — штатный счёт в Telegram Stars.

Бот работает на VDS, `/opt/bilet-bot`, сервис `bilet-bot.service`. Он использует
тот же движок автоочистки, что «Билетная»: распознанные шаблоны KASSIR.RU,
kassy.ru, Ticketland, Intickets, Афиша/МХТ и остальные шаблоны редактора.
Удаляются распознанные ФИО целой строкой и блоки Пушкинской карты, а также
промо-блоки, которые удаляет редактор. Ручные изменения места, цены и текста
из интерфейса редактора не переносятся на произвольные билеты.

## Подписка

1000 Telegram Stars за 30 дней, без лимита обработок. Telegram автоматически
продлевает подписку каждые 30 дней. Доступ открывается только после
`successful_payment`. Повторная доставка подтверждения не продлевает срок;
срок берётся из Telegram. Администраторы `1464797266` и `7868642254` (@FreeDemin) имеют постоянный доступ.

- `/subscribe` — получить персональный счёт.
- `/subscription` — статус и срок доступа; `/dolg` и `/balance` показывают тот же статус.
- `/cancel_subscription` — отключить автопродление, сохранив оплаченный срок.
- `/id` — свой Telegram ID; `/terms` — условия; `/paysupport` — связь с администратором.

Начислений за файлы больше нет. Старый `debts.json` сохранён как архив и не
читается при обработке. Подписки, оплаты, возвраты и очередь хранятся в
`state/subscriptions.sqlite3`. Файл базы нельзя включать в пакет обновления
или откатывать после приёма новых платежей.

Администраторы: `/grant ID_или_@username дни`, `/revoke ID_или_@username` (отзывает только ручной доступ),
`/payments`, `/refund идентификатор_оплаты`, `/payment_issues`.
Цена и администраторы заданы в `subscription.json`. `gift_usernames` выдаёт
разовый бесплатный период при сообщении от указанного Telegram username,
затем привязывает его к числовому ID; приглашение действительно 7 дней.
Для `@FreeDemin` настроен полный доступ администратора (ID `7868642254`), включая выдачу прав.

## Билеты и пачки

Во время обработки бот обновляет одну карточку в чате: получение файла,
очистка, проверка и отправка. Индикатор и таймер меняются примерно каждые
2,5 секунды; для ZIP и /done показано реальное число обработанных PDF и ошибок.
«Всё готово» появляется только после успешной отправки результата. При сбое
Telegram обновление карточки не прерывает обработку; ошибки выдаются отдельно.
В карточке есть короткие мемные реплики МАМЫ про берёзовую кору и покупку
театра. Реплика выбирается случайно для каждого этапа и завершения; при
обновлении таймера текст не прыгает. При ошибке шутка скрывается. Это только
текст карточки: билеты, обработка, кеш и оплата работают как прежде.
Создание и обновление карточки целиком выполняются в отдельном потоке и не
задерживают скачивание или отправку билета. HTTP-соединения Telegram повторно
используются внутри каждого потока; рабочий поток пробуждается сразу при
поступлении задания. В журнале отдельно замеряются скачивание, очистка,
проверка и отправка, без имён и содержимого билетов.

Отправьте PDF документом — получите `<имя>_cleaned.pdf`.
Если изменений нет, исходный PDF возвращается через Telegram file_id с прежним
именем, без повторной загрузки. Успешно отправленные PDF кешируются на 24 часа:
хранятся только закрытые метаданные и Telegram file_id, без байтов билетов.
Кеш изолирован по пользователю и чату, учитывает имя и версию кода редактора.
Повтор того же Telegram-файла выдаётся без скачивания и очистки; совпадение
байтов после нового скачивания тоже позволяет переиспользовать готовый PDF.
Доступ по подписке проверяется перед любой выдачей. Недействительный file_id
удаляется из кеша, затем файл обрабатывается и загружается обычным способом.
Новые PDF/ZIP до 20 МБ передаются Telegram по временной HTTPS-ссылке:
Telegram скачивает точные проверенные байты и присылает обычный документ в чат.
Ссылка не показывается пользователю; файл хранится в памяти, доступ закрывается
после подтверждения отправки. При неопределённом сетевом результате ссылка живёт
до 10 минут, повторная отправка автоматически не выполняется. Если Telegram явно
отказал в скачивании ссылки, используется обычная загрузка. ZIP больше 20 МБ
загружается напрямую. В журнале указан режим url/upload/file_id и время запроса.
В двух реальных первых отправках PDF около 95 КБ путь по ссылке занял 1,018 с,
обычная загрузка через альтернативный сервер Telegram — 53,066 с. Это замер
выдачи после очистки, а не гарантированное полное время: скачивание исходника и
проверка PDF учитываются отдельно.
Для исходника запрос `getFile` идёт по проверенному TLS-соединению Telegram;
при ожидании больше секунды запускается один резервный запрос ко второму
серверу. Используется первый успешный ответ, всего работают не более двух
сетевых потоков. Отказы и полный `retry_after` Telegram соблюдаются.
Журнал разделяет время метаданных, скачивания байтов, очистки и выдачи.
Отправьте ZIP с PDF — получите ZIP и `report.txt` с результатом каждого файла.
Или `/batch`, затем несколько PDF, затем `/done`; отмена `/cancelbatch`.

Входящий файл до 20 МБ; пачка до 50 PDF и 100 МБ распакованных данных.
Выходящий ZIP до 48 МБ. PDF до 100 страниц обычного размера.
ZIP не распаковывается в файловую систему: пути, ссылки, шифрование и объём
проверяются. Неудачные PDF отмечаются в отчёте; остальные выдаются.

Перед выдачей изменённого PDF проверяются число страниц, размер, поворот,
содержимое читаемых QR/штрихкодов, изображение нечитаемых областей, похожих на коды,
распознанные ряд, место, сектор, цена, дата и номер билета. Проверка сравнивает
исходник и окончательно сохранённый PDF. При повреждении файл не выдаётся.
Если изменений не нужно, возвращается точная копия исходных байтов.
У читаемых кодов сравниваются данные, а не пиксели: изменение фона или снятие
надписи программы поверх штрихкода не блокирует выдачу, если данные кода целы.
Для нечитаемых кодов остаётся проверка изображения. Таблица с линиями не
считается штрихкодом без группы параллельных полос. Снятие подписи программы
в этой проверке допускается лишь при восстановлении исходных пикселей под ней.

PDF из `/batch` хранятся в закрытой папке `state/spool` не более часа,
удаляются после выдачи или отмены. Одиночные PDF и ZIP обрабатываются в памяти.
Оплата обрабатывается отдельно от скачивания/очистки; отправка сообщений не
блокирует ответы Telegram на проверку оплаты. Нераспознанные подтверждения
сохраняются для администратора, пользователь получает `/paysupport`.

## Проверка и обновление

Установить зависимости в отдельное виртуальное окружение:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python bot.py --self-test
./Запустить\ бота.command --deploy
```

Обновление через `deploy-vds.sh`: тесты на временном пакете, резервная копия
кода и SQLite, замена кода и перезапуск только `bilet-bot.service`. Токен,
`.env`, очередь, платежи, старые долги и текущие настройки сохраняются.
Для намеренного обновления настроек задайте `BILET_DEPLOY_SETTINGS=1`.
Для первичной подготовки маршрута HTTPS задайте `BILET_GATEWAY_ONLY=1`:
скрипт проверяет приватный маршрут и сохраняет обратимый nginx-бэкап, не меняя
работающий бот. Затем `BILET_ENABLE_URL_DELIVERY=1` при обычном деплое включает
`BILET_PUBLIC_DELIVERY=https://theatralka.ru/-bilet-download` в серверном `.env`.
Остальные переменные сохраняются; при откате восстанавливается исходный `.env`.
Сервис слушает только `127.0.0.1:4313`; nginx не журналирует секретные URL.
Если откат возвращает старую версию с начислениями за файл, сервис остаётся
остановленным; подписки и полученные оплаты не откатываются.

Движок, шрифты и тесты берутся из `BILET_EDITOR` (по умолчанию `~/Билетная`)
и размещаются в `/opt/bilet-bot/biletnaya`; путь задаётся `BILETNAYA`.
Токен: `.token` или `BILET_BOT_TOKEN`. Секреты и пользовательская база не
попадают в пакет. Не запускайте локальный polling одновременно с VDS.
